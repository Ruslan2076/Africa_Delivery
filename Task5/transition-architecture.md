# Transition Architecture — Africa Delivery

Источники: [ADR-001](../task2/adr-001-architecture-style.md) (LB-01…LB-08), [ADR-002](../task3/adr-002-caching-strategy.md), [ADR-003](../task4/adr-003-data-residency.md), [ADR-004](adr-004-payment-provider.md), [roadmap.md](roadmap.md), [tco-model.xlsx](../task2/tco-model.xlsx).

MVP превращается в целевую платформу без переписывания по одной причине: всё, что будет меняться, с первого дня спрятано за швом, и замена идёт по одной стороне шва.

| Шов | Что за ним прячется | Что позволяет заменить без переписывания |
|---|---|---|
| Границы модулей монолита: свои таблицы, вызовы через интерфейсы, архитектурные тесты в CI | Каталог, заказ, оплата, уведомления, продавцы, ПДн | Выделить модуль в сервис (LB-02) — перенос кода и таблиц, а не новая логика |
| Outbox с абстракцией издателя | Managed-очередь сейчас | Перейти на Kafka (LB-03) — сменить реализацию издателя |
| Ключ `country_code` и оверлеи GitOps по странам | Ячейки NG, KE, ZA | Новая страна — конфигурация и партнёры; ответ юриста — перенос данных (ADR-003, REV-01…05) |
| Адаптеры партнёров за интерфейсами `payments`, `shipping`, `notifications` | Flutterwave, Paystack, Sendbox, Sendy, SMS-шлюз | Добавить Daraja (LB-09) или свою логистику (LB-06) — новый адаптер |
| IaC и открытые движки (Kubernetes, PostgreSQL) | AWS, Azure, локальные провайдеры | Сменить провайдера (LB-05, QAS-07) |

## Что меняется на каждом шаге

**Сейчас → MVP.** Строится всё, что на критическом пути (9 функций из 29). Решения, которые дорого изменить позже, фиксируются сразу:
- границы модулей;
- `country_code` в каждой таблице, связанной с субъектом;
- outbox;
- адаптеры партнёров;
- IaC с оверлеями по странам.

Решения, которые дёшево изменить позже, откладываются с триггером: Kafka, сервисная сетка, второй регион, своя логистика.

**MVP → M6.**
- Добавляется ячейка ЮАР в af-south-1: конфигурация, не код.
- Warm standby центра в Azure — по истечении потолка CFO.
- KYC-сервис через адаптер.
- Кабинет продавца — новый модуль в существующей роли «бэк-офис».

**M6 → 12 месяцев.**
- Гана и Кот-д'Ивуар добавляются как ячейки с партнёром Paystack (ADR-004).
- Срабатывающие триггеры отрабатываются по швам:
  - LB-03 — замена издателя outbox на Kafka;
  - LB-02 — перенос модуля каталога в отдельный деплой с собственной БД; таблицы уже не делятся с другими модулями;
  - LB-09 — новый платёжный адаптер.
- Пересматривается LB-06 со своей логистикой: если она окупается, она встаёт за интерфейс `shipping` рядом с адаптерами Sendbox и Sendy и включается по стране.

## Чего не будет на пути

Ни на одном шаге нет «большого переписывания»:
- монолит не переписывается на микросервисы целиком;
- платёжный контур не переписывается под нового партнёра;
- данные не переносятся между странами.

Каждый шаг — добавление или замена за одним швом, проверяемое архитектурными тестами и учениями из [failover-plan.md](../task4/failover-plan.md).
