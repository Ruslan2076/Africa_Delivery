# Africa Delivery

Архитектура мультикатегорийного маркетплейса для Нигерии и Кении с последующим выходом в ЮАР и ещё 12–15 стран. Запуск 15 октября, бюджет $5 000/мес на всё техническое, шесть контракторов, данные граждан не покидают свою страну.

Работа выполнена на основе восьми входных артефактов: транскрипт встречи с инвестором, маркетинговый бриф, письмо юриста, список функций PM, письма CTO и CFO, записка инвестора, схема системы. В документах они упоминаются как «арт. 1…8». Описание компании и целей бизнеса называется «Вводная».

## Ключевые решения

| Решение | Суть | Главная цифра |
|---|---|---|
| [ADR-001](task2/adr-001-architecture-style.md) — архитектурный стиль | Модульный монолит на Go вместо 40–50 микросервисов; доступность наращивается по экономике | TCO за 5 лет без транзакционных расходов — $8,9 млн против $15,5 млн у варианта CTO |
| [ADR-002](task3/adr-002-caching-strategy.md) — кеширование | Многоуровневый кеш; TTL и инвалидация заданы для каждого класса данных, остатки и ПДн не кешируются | ≤ 10% запросов каталога доходят до БД |
| [ADR-003](task4/adr-003-data-residency.md) — размещение данных | Всё, что связано с субъектом, живёт в ячейке его страны; центр в AWS af-south-1 — без ПДн; решение обратимо без переписывания кода | $4 530/мес из $5 000 |
| [ADR-004](task5/adr-004-payment-provider.md) — платёжный провайдер | Flutterwave и Paystack в Нигерии, Paystack с M-Pesa в Кении, своя тонкая маршрутизация | ≈1,6% GMV при потолке 2,5% |

Из 29 функций списка PM в MVP входят 9, остальные распределены по 6 и 12 месяцам или отклонены ([roadmap.md](task5/roadmap.md)).

## Соглашения

- **Источники.** Каждое решение ссылается на артефакт и пункт, из которого оно выросло, например «арт. 6, п. 3».
- **Допущения** собраны в разделе `## Assumptions` того документа, где используются. Нумерация сквозная по всей работе: A-01…A-38.
- **Сквозные идентификаторы** одинаковы во всех заданиях:

  | Префикс | Что обозначает | Где введён |
  |---|---|---|
  | STK | Стейкхолдеры | Задание 1 |
  | C | Противоречия | Задание 1 |
  | Q | Вопросы стейкхолдерам | Задание 1 |
  | G, D, CN, R | Цели, драйверы, ограничения, риски | Задание 1 |
  | OPT | Варианты архитектуры | Задание 2 |
  | CTO | Пункты предложения CTO | Задание 2 |
  | LB | Отложенные решения и их триггеры | Задания 2, 5 |
  | UC | Сценарии использования | Задание 2 |
  | P | Архитектурные принципы | Задание 2 |
  | NFR | Нефункциональные требования | Задания 2, 3 |
  | SLI | Индикаторы уровня сервиса | Задание 3 |
  | QAS | Сценарии атрибутов качества | Задание 3 |
  | FM | Виды отказа | Задание 3 |
  | DC | Категории данных | Задание 4 |
  | REV | Сценарии обратимости | Задание 4 |
  | F | Сценарии отказа | Задание 4 |
  | CAP | Возможности | Задание 5 |
  | RR | Риски roadmap | Задание 5 |

- **Диаграммы.** PlantUML 1.2024.7 со стандартной библиотекой C4-PlantUML; roadmap — Mermaid Gantt. Рядом с каждым исходником `.puml` лежит отрендеренный `.png`.
- **Формат.** Markdown, имена файлов в kebab-case. Исключения: модель TCO (`.xlsx`) и слайд для Найроби (`.pptx`).
