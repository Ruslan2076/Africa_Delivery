# ADR-002: Кеширование многоуровневое, у каждого класса данных свой TTL и способ инвалидации

**Дата:** 25.08.2026
**Статус:** Принято
**Связанные документы:** [ADR-001](../task2/adr-001-architecture-style.md), [nfr-registry.md](nfr-registry.md), [fmea.md](fmea.md)

## Контекст

Каталог — первый экран после рекламы: 50 тыс. одновременных сессий в неделю запуска (A-01), меньше 2 с до первого товара на 3G (арт. 2), премиальные фото с зумом при дорогом трафике аудитории (арт. 2, C-10). Связь обрывается (Вводная, «Технологический стек»). При отказе ядра каталог должен открываться (NFR-14). Бюджет — $5 000/мес, сейчас занято $4 450 (tco-model.xlsx, TCO_A). Персональные данные не покидают страну (арт. 3, п. 1). Остатки во время флеш-распродажи нельзя продать дважды (QAS-04).

Рассмотренные варианты:

1. **Только CDN, без кеша приложения.** Самый дешёвый. Каждый промах CDN — запрос в PostgreSQL. При холодном кеше в начале эфира БД получает до 1 000 RPS чтения карточек (A-19), и пул соединений делится с оформлением заказа (FM-07). Отклонён.
2. **Redis как универсальный кеш и хранилище:** карточки, остатки, сессии, корзины, профили. Остатки в Redis расходятся с БД при сбое и дают продажу сверх остатка. Профили с ПДн в центральном Redis нарушают резидентность. Без TTL по классам данных кеш становится вторым, несогласованным источником истины. Отклонён.
3. **Многоуровневый кеш с явной таблицей «что / где / TTL / инвалидация».** Принят.

## Решение

| Данные | Где кешируется | TTL | Инвалидация | Источник истины |
|---|---|---|---|---|
| Изображения товаров | CDN + кеш приложения | 1 год (неизменяемые) | Не нужна: URL содержит хеш содержимого, новая версия — новый URL | Объектное хранилище |
| Карточка товара (описание, атрибуты, продавец) без цены и остатка | CDN → Redis (Cache-Aside) → приложение | CDN 5 мин; Redis 10 мин; приложение 24 ч в офлайне | Событие `product.updated` из outbox: удаление ключа Redis и purge в CDN по surrogate key. TTL — страховка при потере события | PostgreSQL |
| Списки категорий и выдача поиска | CDN → Redis | CDN 2 мин; Redis 5 мин | Только TTL: устаревание на 5 мин допустимо | PostgreSQL |
| Цена и остаток для отображения | CDN | 15 с | Purge по surrogate key при старте и окончании флеш-распродажи | PostgreSQL |
| Остаток при оформлении заказа | **Не кешируется** | — | — | PostgreSQL, атомарное резервирование |
| Статусы заказа и оплаты | Приложение (только чтение для офлайна) | До следующего ответа сервера | Перезапрос при открытии экрана и по push | PostgreSQL |
| Агрегаты дашборда запуска | Redis | 60 с | Только TTL: дашборд обновляется раз в минуту (арт. 2) | PostgreSQL |
| ПДн: имя, телефон, адрес | **Не кешируются вне страновой ячейки** | — | — | Страновая ячейка |
| Одноразовые коды входа (OTP) | Redis в страновой ячейке | 5 мин | Удаление после использования | Redis ячейки (хранилище, не кеш) |

**Поведение при отказах.**
- Ядро недоступно: CDN отдаёт устаревший ответ до 24 ч (`stale-if-error`), приложение показывает офлайн-кеш.
- Redis недоступен: чтение идёт в реплику PostgreSQL с ограничением конкурентности (FM-10).
- Защита от лавины промахов: при промахе в БД идёт один запрос на ключ (request coalescing), к TTL добавляется случайный разброс ±10%.

**Размещение.** Managed Redis, один экземпляр с репликой в другой зоне, ≈$80/мес. Перед эфиром кеш прогревается списком из 500 самых популярных карточек.

## Последствия

**Положительные.** До PostgreSQL доходит ≤ 10% запросов каталога, роль «checkout» не конкурирует с каталогом за БД. Каталог доступен при отказе ядра, это даёт SLO 99,95% (`slo/catalog.md`). Офлайн-кеш экономит трафик покупателя.

**Отрицательные.** Покупатель может видеть описание товара, устаревшее до 5 мин, а цену — до 15 с. Финальная цена всегда пересчитывается при оформлении заказа, поэтому покупатель изредка увидит «цена изменилась». Нужна дисциплина событий: каждое изменение товара обязано пройти через outbox. Облако дорожает на ≈$80/мес: $4 530 из $5 000.

**Риски.** Потерянное событие инвалидации оставляет устаревшую карточку на срок TTL; это допустимо. Неверный surrogate key не очистит CDN, поэтому purge проверяется в интеграционных тестах. Регресс доли попаданий в CDN ниже 90% — алерт ([observability.md](observability.md)).

## Assumptions

- A-01. Пик первой недели — 50 тыс. одновременных сессий.
- A-19. Один запрос в 5 с на сессию, 90% попаданий в CDN.
- A-22. Managed Redis минимального класса с репликой — ≈$80/мес в африканском регионе.
