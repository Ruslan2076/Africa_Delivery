# SLO-контракт: уведомления

**Сервис:** модуль уведомлений (SMS, WhatsApp Business API, push; учёт согласий) · **Владелец:** команда ядра · **Потребители:** модули заказа и оплаты, покупатели и продавцы (UC-08, UC-14) · **Окно:** скользящие 30 дней · **Метод бюджета:** по событиям

Уведомления асинхронны: заказ подтверждается покупателю на экране, даже если шлюз недоступен. Поэтому доступность модуля как API пользователю не видна. Измеряются своевременность и отсутствие потерь. Транзакционные и маркетинговые сообщения идут раздельно, SLO действует только для транзакционных.

## SLI — что и как измеряется

| ID | Индикатор | Хорошее событие | Все события | Где измеряется |
|---|---|---|---|---|
| SLI-NTF-01 | Своевременность | Транзакционное уведомление (оплата, отправка, выдача, заказ продавцу) принято шлюзом за 60 с от события | Все транзакционные события из outbox | Разница `event_time` и ответа шлюза, метрика `notification_dispatch_seconds` |
| SLI-NTF-02 | Отсутствие потерь | Уведомление принято шлюзом хотя бы по одному каналу за 1 ч | Все транзакционные события | Сверка outbox с журналом отправок |
| SLI-NTF-03 | Доставка | Шлюз подтвердил доставку на устройство за 5 мин | Отправленные SMS и WhatsApp | Delivery receipts шлюзов |
| SLI-NTF-04 | Соблюдение согласий | Маркетинговое сообщение ушло только пользователю с действующим согласием | Все маркетинговые отправки | Аудит журнала согласий |

## SLO — целевые значения

| SLI | Цель | Бюджет ошибок за 30 дней |
|---|---|---|
| SLI-NTF-01 | 99% | 1% уведомлений позже 60 с |
| SLI-NTF-02 | 99,9% | 1 потерянное уведомление на 1 000 |
| SLI-NTF-03 | 95% | 5%: доставляемость зависит от операторов связи |
| SLI-NTF-04 | 100% | Нет: любое нарушение — инцидент (арт. 3, п. 2) |

```yaml
apiVersion: openslo/v1
kind: SLO
metadata:
  name: notifications-timeliness
spec:
  service: notifications
  indicator:
    metadata: { name: sli-ntf-01 }
    spec:
      ratioMetric:
        good:  { metricSource: { type: prometheus, spec: { query: 'sum(rate(notification_dispatch_seconds_bucket{class="transactional",le="60"}[5m]))' } } }
        total: { metricSource: { type: prometheus, spec: { query: 'sum(rate(notification_dispatch_seconds_count{class="transactional"}[5m]))' } } }
  timeWindow: [ { duration: 30d, isRolling: true } ]
  budgetingMethod: Occurrences
  objectives: [ { displayName: timeliness, target: 0.99 } ]
```

## SLA — что гарантируется и что при нарушении

| Кому | Обязательство | При нарушении |
|---|---|---|
| Бизнес (STK-04) | ≥ 97% транзакционных уведомлений в шлюзе за 60 с, за месяц | Разбор, пересмотр маршрутизации каналов |
| Продавцы (STK-10) | Заказ приходит в WhatsApp за 5 мин | Дублирование SMS; при повторе — переход продавца на кабинет |
| Регулятор (STK-07) | Ни одного маркетингового сообщения без согласия | Остановка всех маркетинговых рассылок до устранения, уведомление юриста |

Маркетинговая рассылка дня запуска (арт. 2) идёт через отдельную очередь и пул отправщиков. Её объём не может вытеснить транзакционные уведомления ([fmea.md](../fmea.md), FM-04).
